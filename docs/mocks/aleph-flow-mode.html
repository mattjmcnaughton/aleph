A drawing to argue with, not a decision. The numbered pins mark the calls each screen encodes; they are collected at the foot of the page, where three are now settled (client-side only, a Random order, no minutes estimate) and the rest are still yours. Screens 02 and 03 are live — tap around.

Vocabulary

Three words, if we build it

Proposed for docs/CONTEXT.md once the details are settled — nothing below is in the vocabulary yet. "Flow mode" is the feature's working name; the noun the product would use is simply a Flow.

TermMeaning
FlowA bounded run of lessons taken one after the other, where each completed lesson opens the next without the learner choosing. Scoped at the door by a Flow length and a Flow scope; ends when the length is reached, the scope runs dry, or the learner ends it. A run of ordinary lessons — every completion inside it is an ordinary Mark complete.
Flow lengthHow many lessons the flow will take — a count (3, 5, 8), or open-ended ("until I stop"). Fixed at the door; the only thing that changes it mid-flow is ending it.
Flow scopeWhich paths the flow draws lessons from, and in what order — interleaved (paths take turns), random (a path drawn afresh for every lesson), or one path at a time. Within a path the order is always Progression's: the next available lesson. Always paths — a Beat is not a path and a Brief is not a lesson.
Decisions

What the drawing assumes, and what it leaves to you

Each card is one call. settled means you have decided it; drawn means the screens above encode a recommendation; open means the screens picked something so they could be drawn, and the real answer is yours.

1 Where the door is

Home, directly under Continue — the place a learner already goes to resume. A path view gets the same door with that path pre-selected. No header pill: a flow is a thing you start, not a thing you are owed.

drawn Route: /flow/new as a sheet over home; /flow/new?path=… from a path.

2 Scope at the door

Length and paths are set once, before the first lesson. Inside the flow the only control is End flow. Widening is offered where it is wanted — at the end, as Go again — exactly as review offers "Review those too".

drawn Same rule as Phase 3 PRD §4.10. A mid-flow "add 3 more" is the first thing to argue for if you disagree.

3 Order across paths

Three orders when two or more paths are picked. Interleave takes turns (TypeScript, SQL, TypeScript…). Random draws a path afresh for every lesson. One path at a time finishes the first before touching the next. In every order a path's own lessons stay linear — Random picks the path, and then that path's next available lesson, because Progression is unchanged.

settled Interleave is the default. Random draws with the same anti-starvation rule the review queue uses: a path just taken is not excluded, but with "until I stop" no path can be skipped forever.

4 How the advance happens

Drawn as a 5-second count after Mark complete, with Go now and Pause. The count exists so the Quick check explanation can be read; the pause exists so a learner can stop and ask the tutor. Opening the rail should pause it too.

open The number (3? 5? 8?), and whether an incorrect Quick check gets a longer count than a correct one. Instant-advance with an undo toast is the other shape.

5 Drafts wait for the end

Auto-draft keeps drafting as each lesson opens; the keep/discard moment moves to the flow's end as one batch of 11 rather than five interruptions of 3–4. A learner who ends the flow early still gets the batch.

open Whether an ended-early flow shows the batch, or drops back to today's per-lesson behaviour for the lesson it stopped on.

6 Nothing new is stored

A flow is client state: a length, a list of path ids, an order, a cursor. Every completion is an ordinary Mark complete; streaks, Active day and Activation are untouched. No table, no route on the backend, no migration.

settled 100% client-side. Survives a reload via the URL (?flow=…) or session storage; does not survive leaving. A flow is a Session, and a Session is 30 minutes. The one backend touch left is the early generation trigger below, which is an existing endpoint called sooner.

When a path runs out

A path with nothing left drops out of the scope and the flow continues on the rest. When every path is dry the flow ends early with the same receipt, saying so ("3 of 5 — SQL performance is finished"). A flow never grows a path; that is shaping's job.

drawn The sheet already caps the button at what is left, so this is rare and never a surprise.

Generation latency

The one backend touch. Prefetch (+N) looks ahead on one path; an interleaved flow knows its next lesson is on a different path. The flow should ask for that lesson's generation as soon as the current one opens.

drawn Reuse trigger + poll: the client fires the next lesson's existing generation trigger early. No new endpoint; the count doubles as the latency hider.

Do due cards belong in a flow?

The tempting version: "5 lessons and your 10 due cards" — one sitting, both habits. It would also make a flow the first surface that mixes a lesson and a review, which are counted, scheduled and celebrated differently.

open Drawn lessons only. Cards stay behind their own door; the receipt could offer "10 due" as the next thing, which is a link, not a merge.
